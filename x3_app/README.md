# X3 – Intrams Scoreboard & Schedule

CSIT284 Capstone · Flutter + Cloud Firestore

A mobile app for monitoring school intramurals. Students view match schedules,
watch live scores update in real time, and check team standings. One hidden
"admin" area manages teams, matches and scores.

## Features

**Student side**
- **Home dashboard**: app name/logo, live match, upcoming matches, recent results, team and match counts, quick links to Schedule and Standings.
- **Match schedule**: Match ID, Team A/B, date, time, venue, status, with filters (All / Upcoming / Live / Completed).
- **Live scoreboard**: team names + logos, current score, status, date/time, venue, *last updated*. Updates in real time via Firestore snapshot listeners (no manual refresh).
- **Team standings**: Rank, Team, GP, W, L, PD, PTS. Win = 3 pts, Loss = 0. Ties broken by point difference. Recalculated automatically.

**Admin side (single area, demo PIN)**
- Add / edit / delete matches
- Update live scores (quick -1 / +1 / +2 / +3 buttons)
- Change status (Upcoming → Live → Completed)
- Manage teams (add / edit / delete)
- Load / remove clearly-flagged **sample data**
- Confirmation dialogs for delete and for completing a match

## Firebase setup
1. Create a project at <https://console.firebase.google.com>.
2. Build → **Firestore Database** → *Create database* (production mode, nearest region).
3. Install tools:
   ```bash
   dart pub global activate flutterfire_cli
   npm install -g firebase-tools && firebase login
   ```
4. In the project root run `flutterfire configure`, pick your project and the Android platform. This **overwrites `lib/firebase_options.dart`**.
5. Firestore → **Rules** → paste the contents of `firestore.rules` → Publish.

## Firestore structure
**`teams/{teamId}`**: `teamId, teamName, logoUrl, gamesPlayed, wins, losses, points, pointsScored, pointsAgainst, pointDifference, isSample`

**`matches/{matchId}`**: `matchId, teamAId, teamBId, teamAName, teamBName, scoreA, scoreB, sportCategory, matchDate (Timestamp), matchTime ("HH:mm"), venue, status (upcoming | live | completed), createdAt, updatedAt, isSample`

Document IDs are Firestore auto-IDs (sample docs use readable IDs like `sample_M01`).
Team stats are **derived**: every match save/delete recalculates all team records
from completed matches and commits the match write + standings update in **one
batched write**, so edits and deletions can't leave standings inconsistent.

## Sample data
"Load sample data" creates 4 teams (Phoenix, Titans, Warriors, Falcons), 2 completed
matches, 1 live match, 2 upcoming matches. Every record has `isSample: true`, shows a
SAMPLE tag, and **Remove sample data** deletes only those records.

## Security note (demo only)
The admin PIN is stored in the app (`utils/constants.dart`) and is **not real
security**. Because there is no authentication, Firestore cannot tell admins from
students. `firestore.rules` therefore allows public read, validates the shape of
every write, and **stops accepting writes after 2026-12-31**. For production, add
Firebase Authentication and require an admin claim for every write.

## Known limitations
- Demo PIN is not real security (see above).
- No tie/draw handling: completed matches must have a winner.
- Logos are optional URLs; no image upload.
- Standings recalculation reads all matches; fine for one small tournament, not for large data.
- Two admins editing the same match at the exact same moment: last write wins.
